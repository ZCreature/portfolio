Case study — 02 / Tooling & accessibility

I built an accessibility tool, shipped it, and found my own colour maths was wrong.

Color Safety Lens audits palettes for contrast and colour-vision deficiency. The first working version gave confident, authoritative, wrong answers — off by more than ΔE 14 on some hues, where 1.0 is a visible difference.

Role

Design, research, build

Year

2026

Stack

Figma, VS Code, vanilla JS

Status

Open source, in use

01 — The problem

Brand colour almost never ships at 100%

Every brand guideline specifies colour at full strength. In a dashboard that colour spends its life at 60%, 30%, 10% — fills, ramps, banding, disabled states. The guideline says nothing about those. That's where accessibility quietly breaks.

I was checking tints one at a time on webaim.org, dozens per dashboard, across fifty. Slow — and worse, it was sampling. I only caught failures I thought to look for.

02 — The failure

Doing the maths on the JPEG instead of the RAW

I used the Machado, Oliveira & Fernandes (2009) model — the standard CVD matrices. Read the values in, multiply through the matrix, write them back out. It rendered. It looked plausible. I shipped it.

The matrices operate on linear RGB — light as a physical quantity. Hex values in a design file are gamma-encoded sRGB, pre-distorted for how displays and eyes work. I was running a physics model on perceptual numbers.

If you shoot photography: I was doing the maths on the JPEG instead of the RAW.

03 — The fix

Rebuild the pipeline, then prove it

Fixing the code took an afternoon: linearise in, apply, re-encode out. Trusting it again took much longer.

  • Rebuilt in linear RGB. Every operation — simulation, tinting, mixing — happens in linear space and converts back at the boundary.
  • Validated ΔE against Sharma's test suite. CIEDE2000 has known discontinuities that naive implementations get wrong. The published test data exists to catch them.
  • Ran Okabe–Ito through as a control. It's the palette designed by colourblind scientists to stay distinguishable. If my tool flagged it unsafe, my tool was still broken.

Five audits later, it passed clean.

04 — Where it landed

What the tool actually changed

Verified tints export as SVG straight back into Figma — into the design system, not a screenshot folder. The audit stopped being a final step and became part of the definition of done.

The honest lesson

AI-assisted development got me to "working" in an evening. Working and correct are different claims, and a tool that audits accessibility has to earn the second. The first version was fast, confident and wrong — and nothing in the interface said so.

I'm a designer, not an engineer. The lesson isn't to stop building tools. It's that building them obliges me to know what my artefacts claim on my behalf.
